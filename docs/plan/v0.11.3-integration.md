### 2.1 이번 세션 스코프 (사용자 지시)

- **Stage 1 (계획)** + **Stage 2 (계획 검증)** + **Stage 3 (로컬 병합 + 정적 검증)**까지.
- **push 없음. RC 태그 없음. PR 없음. 배포 없음.**

### 3.1-a #29280 `raise`의 실패 모드 (v2 신규)

- `run_migrations()`는 `config.py` **모듈 import 시점**에 `if ENABLE_DB_MIGRATIONS:` 아래에서 호출된다. `raise`가 전파되면 `import config` 자체가 실패 → FastAPI 기동 전 프로세스 사망. `docker-compose.deploy.yaml`은 `restart: unless-stopped` → **재시작 루프**.
- **fork 프로덕션 영향**: healthy ≠ 마이그레이션 성공 (구 코드는 예외를 삼키고 시작 = #29280 실패 모드 그 자체). 근거는 §1 — kwh.2 배포 기록상 프로덕션은 `d4c1a8e37b62` 이후, `PRAGMA integrity_check` = `ok`. v0.11.3은 신규 마이그레이션 0건 → `command.upgrade(cfg, 'head')`는 no-op → 예외 없음 → 무해.
- **위험 시나리오**: 로컬 게이트가 프로덕션 파생 데이터로 기동 실패 + 마이그레이션 예외 로그 → 이는 **병합 결함이 아니라 프로덕션 DB가 이미 half-applied 상태**임을 뜻한다. 이 경우 **최종 태그를 만들지 말고 DB부터 조사·복구**. (§10 롤백 트리거 참조) §8.3에서 프로덕션 파생 데이터셋의 `alembic_version` = head, `PRAGMA table_info(chat)`에 `timer_at` 존재를 사전 검증.
- **확인 완료 (2026-09-02) — 리스크는 실재한다**: 프로덕션 `.env.openwebui.oauth`에 `ENABLE_DB_MIGRATIONS`가 **설정돼 있지 않다**. `backend/open_webui/env.py:151`은 `os.getenv('ENABLE_DB_MIGRATIONS', 'True')` — 즉 **기본값 True**이고, compose도 이 변수를 주입하지 않는다. 따라서 프로덕션에서 **마이그레이션은 실행되며 `raise`는 도달 가능**하다. 본 항목은 정보성이 아니라 **실제 리스크**로 취급한다.
  - 완화: v0.11.3은 신규 마이그레이션 0건이므로 `command.upgrade(cfg, 'head')`가 no-op이어야 정상이다. 로컬 게이트(§8.3)에서 프로덕션 파생 데이터로 기동해 예외가 없음을 **반드시** 확인한 뒤에만 최종 태그로 진행한다.
