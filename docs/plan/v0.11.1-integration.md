## 1. Context

upstream `open-webui/open-webui`가 2026-08-25에 `v0.11.1`을 릴리스했다. 우리 fork(`kwh8121/openwebui-service`)의 최신 프로덕션 이미지는 `v0.11.0-kwh.1`이다.

Linear 프로젝트 `openwebui v0.11.1`은 이미 workspace `koreatimes`에 Backlog 상태로 존재하지만 v0.11.1 통합 이슈는 아직 생성되지 않았다(현재 하위 이슈는 KOR-5~8 Runner health monitoring 계열뿐).

v0.11.1은 **보안 권고 포함 대규모 릴리스**이며 실질 병합 스코프가 커서 5-stage 워크플로 전 단계를 정상 경로로 통과시켜야 한다. 로컬 검증(`scripts/local-test.sh`)은 stage 4에서 RC 이미지에 대해, stage 5 직전에 최종 태그에 대해 두 번 실행된다.

## 2. 목표

- upstream `v0.11.1` 소스를 fork에 병합하고 fork 고유 커스터마이징을 무손실로 보존한다.
- 5-stage 워크플로(Linear stage 1~4 + GitHub stage 5)를 정상 경로로 통과한다.
- 로컬 프로덕션 미러 게이트(`docs/plan/local-test-workflow.md` §3.6-b)를 두 번 통과한 뒤에만 프로덕션에 배포한다.
- 프로덕션 데이터 upgrade 마이그레이션 무결성(로컬 축적 데이터 기반)을 사전에 검증한다.

## 7. Stage 3 (개발) — 병합 전략

### 7.1 브랜치 흐름

```
feature/upstream-merge-v0.11.1
  ← git merge upstream v0.11.1 (또는 rebase 방식, 충돌 규모에 따라 결정)
  ← 커스터마이징 재적용 (필요 시 별도 feature 브랜치로 분리)
  ↓
integration/v0.11.1 (신규)
  ← feature/upstream-merge-v0.11.1 (--no-ff)
  ← feature/브랜드-재적용 (필요 시, --no-ff)
  ← feature/suggestion-prompt-보존 (필요 시, --no-ff)
  ↓ (stage 4 통과 후)
main (via PR)
```

`AGENTS.md` §"Release Routine And Session Continuity" 원칙:

- 절대 `main` 직접 커밋 금지
- 모든 변경(문서 포함) `feature/* → integration/vX.Y.Z → PR → main` 경로

### 7.2 병합 방식

`git merge upstream/v0.11.1`로 namespaced 태그를 직접 병합한다. 이동 가능한 `upstream/main`이나 기존 로컬 `v0.11.1` 태그는 사용하지 않는다.

### 7.3 병합 준비 커맨드 (참고)

**주의 — upstream 태그 clobber**: fork에 이미 존재하는 `v0.10.2`/`v0.11.0`/`v0.11.0-kwh.*` 태그가 upstream의 동명 태그와 충돌해 `git fetch upstream --tags`가 `rejected (would clobber existing tag)`로 실패한다. 다음 중 하나로 대응:

- **권장**: `git fetch upstream --no-tags` — 태그를 가져오지 않고 브랜치만 갱신한다.
- **필수 태그만 별도 저장**: `git fetch upstream refs/tags/v0.11.1:refs/tags/upstream/v0.11.1` — upstream 태그를 `upstream/` 네임스페이스로 분리 저장한다.
- **비권장**: `git fetch upstream --tags --force` — fork 태그 덮어씀. 릴리스 이력 손상 위험.

```bash
# 초기 상태 확인
git fetch upstream --no-tags                                    # 태그 clobber 회피
git fetch upstream refs/tags/v0.11.1:refs/tags/upstream/v0.11.1 # v0.11.1만 분리 저장
git fetch origin --prune

# feature 브랜치 생성 (검토된 integration 브랜치 기점)
git checkout integration/v0.11.1 && git pull --ff-only
git checkout -b feature/upstream-merge-v0.11.1

# 병합 (분리 저장한 태그 참조)
git merge upstream/v0.11.1          # upstream 태그를 upstream/ 네임스페이스로 참조
# 충돌 예상 파일: static/static/*.png, WEBUI_NAME 관련 파일,
# suggestion prompt 관련 파일, 그 외 CHANGELOG/pyproject.toml/package.json

# 충돌 해결 후 fork 자산 우선 재적용, 커밋
git commit
```
