## 1-A. v0.11.1 ~ v0.11.3 신규 변경사항 (2026-09 갱신)

### A-1. Tavily 관련 — 최우선 확인 항목

**Tavily를 web loader로 쓸 때 페이지 읽기가 v0.10.0부터 v0.11.0까지 계속 실패하고 있었고, v0.11.1에서 수정되었습니다.**

프로젝트는 Tavily를 primary web search tool로 확정한 상태이므로 이 항목이 가장 직접적입니다. 현재 운영 버전이 v0.10.x 또는 v0.11.0이라면 Research Desk의 "링크 읽기" 경로가 조용히 실패하고 있을 가능성이 있습니다. (추측: 실제 운영 버전을 확인하지 않았으므로 증상 발생 여부는 검증 필요)

추가로:

- **`TAVILY_API_BASE_URL`** 신설 (v0.11.1). Tavily 검색·페이지 fetch를 다른 주소로 보낼 수 있습니다. 사내 게이트웨이를 경유하거나 호환 서비스로 교체할 때 사용합니다.
- **웹 검색 실패 시 이유를 표시** (v0.11.1). 이전에는 검색 엔진만 선택하고 API 키를 넣지 않으면 아무것도 반환하지 않고 조용히 끝났습니다. Tavily Free 플랜 1,000 queries/month 소진 시 원인 파악이 쉬워집니다.
- **Playwright 로더 egress 경로 변경** (v0.11.1). 페이지의 이미지·스크립트·CSS 요청을 브라우저가 아니라 OpenWebUI 백엔드가 수행합니다. 원격 브라우저(`PLAYWRIGHT_WS_URL`)를 쓰면 트래픽 출발지가 백엔드 주소로 바뀌고, 사설 CA는 `AIOHTTP_CLIENT_SSL_CERT_FILE`로 신뢰시켜야 합니다. 동기 경로에서는 자산을 순차 요청하게 되어 느려집니다 — 공식 측정치로 자산 30개 페이지가 2.0초 → 3.0초, 느린 자산 8개 페이지가 1.1초 → 4.5초.

### A-2. Human-in-the-loop 도구 승인 (v0.11.1)

관리자가 켜두면, 사용자가 대화 단위로 "도구를 자유롭게 실행" ↔ "실행 전에 물어보기"를 전환할 수 있습니다. 모델이 도구를 쓰려 하면 호출 1건씩 멈추고 허용/거부를 기다립니다. 선택은 해당 대화와 이후 대화에 기억됩니다. **Automation, 채널 답글, 임시 채팅은 이 승인 흐름의 적용을 받지 않습니다.**

**MVP 영향 (중요):** V2에서 P0로 승격한 Trust Layer(Fact Checker)의 구현 난이도를 낮춥니다. 기자가 팩트체크 도구 호출을 직접 승인/거부하는 UX를 코드 없이 확보할 수 있습니다. 다만 자동화 경로에는 적용되지 않으므로, 무인 실행되는 보도자료 파이프라인(SG3)의 안전장치로는 쓸 수 없습니다. SG3는 여전히 Pipe Function의 결정적 실행으로 통제해야 합니다.

### A-3. 관리자 전역 설정 3종 (v0.11.1) — 표준화 목표에 직결

프로젝트의 핵심 목표가 "조직 전반의 AI 사용 표준화"이므로 이 3개가 실무적으로 가장 유용합니다.

| 설정                             | 내용                                                                                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`DEFAULT_INTERFACE_SETTINGS`** | Settings의 인터페이스 옵션에 대한 전사 기본값을 관리자 패널 또는 환경변수로 지정. 개인이 바꾼 항목은 개인 설정이 우선, 손대지 않은 항목은 "상속됨"으로 표시되며 이후 기본값 변경에 계속 따라감 |
| **`TASK_MODEL_PARAMS`**          | 제목·태그·후속질문·검색쿼리·대화요약 등 백그라운드 작업의 생성 파라미터 지정. 이전에는 토큰 상한이 고정이라 요약이 잘리는 문제가 있었음                                                        |
| **CSV로 그룹 멤버 일괄 추가**    | 이름·이메일 CSV 업로드로 그룹에 다수 인원 추가. 템플릿 다운로드 제공, 계정 없는 행은 안내                                                                                                      |

**MVP 영향:** 시드 그룹 3~5명 → 데스크 단위 베타 → M6 전사 롤아웃 순서에서, CSV 일괄 추가가 온보딩 수작업을 줄입니다. `TASK_MODEL_PARAMS`는 보도자료 요약 품질(잘림 방지)에 직접 영향을 주니 SG3 검증 항목에 넣으세요.

### A-4. `request` 필터 훅 신설 (v0.11.2)

Filter 작성자가 `request`를 사용해 **모델 호출 직전에 payload를 조정**할 수 있습니다. 도구 사용 후 이어지는 후속 호출에도 적용됩니다. 기존 `inlet` / `stream` / `outlet`은 그대로 동작합니다.

**용어 정리 (독학 개발자 대상):** OpenWebUI의 Filter Function은 요청/응답이 지나가는 지점에 끼어드는 훅입니다. 기존에는 `inlet`(사용자 메시지가 들어올 때) → `stream`(응답 조각마다) → `outlet`(응답 완료 후) 3개뿐이라, "실제 LLM에 나가는 최종 payload"를 건드릴 지점이 없었습니다. `request`가 그 자리를 채웁니다.

**MVP 영향:** 현재 임시 방편인 Rate Limit Filter Function + OpenRouter 크레딧 상한 조합에서, `request` 훅으로 모델 파라미터를 호출 직전에 강제(예: 특정 사용자 그룹의 `max_tokens` 상한)할 수 있습니다. `inlet`에서 하던 것보다 정확한데, 도구 호출 후 발생하는 추가 LLM 호출까지 잡히기 때문입니다. 비용 관리 항목 재검토 대상.

### A-5. 성능 — 스트리밍 전면 재작성 (v0.11.1)

응답이 "지금까지의 전체 메시지 재전송"에서 "새 텍스트 조각만 전송"으로 바뀌었습니다. 전송량이 응답 길이의 제곱이 아니라 길이에 비례하게 됩니다. 매우 긴 응답 기준 전송량과 서버 append 작업이 **최대 1000배** 감소합니다. Redis 백엔드에서는 진행 중인 응답이 서버에 보관되어, 새로고침 후 대화를 다시 열면 빈 메시지 대신 진행 상태를 이어받습니다.

그 외 v0.11.1에서 확인된 구체적 수치:

- 채팅 15,000건 인스턴스에서 사이드바 목록·읽지 않음 카운트가 2~4초 걸리던 것 해소
- 긴 응답의 reasoning/코드블록 재파싱 약 190배 감소
- 200개 메시지 대화에서 소스/파일 첨부 1건당 3.1ms → 0.65ms
- 유휴 인스턴스가 매초 전체 채팅을 훑으며 타이머를 찾던 동작 제거 (대용량 히스토리에서 CPU 코어 약 1/4 상시 점유, 메모리 고갈로 프로세스 종료 가능성 있었음)
- 로그인 상태 기록 쓰기가 요청마다 → 사람당 최대 분당 1회 (탭만 열어둬도 분당 2건 쓰기 트랜잭션 발생하던 문제)
- 요청이 통과하던 미들웨어 레이어 5개 → 1개
- **신규 환경변수**: `UVICORN_WS_PER_MESSAGE_DEFLATE`(실시간 업데이트 압축 해제), `WEBSOCKET_HEARTBEAT_INTERVAL`(기존 30초 고정), `REDIS_RESPONSE_STREAM_TTL`(미완료 응답 상태 만료), `THREAD_POOL_THREAD_NAME_PREFIX`

**MVP 영향:** 단일 서버 + 기자 수십 명 규모라면 v0.11.1 이후 성능 여유가 충분합니다. 이 리포트 2-5장의 "무거운 작업만 외부 FastAPI로 분리" 하이브리드 전략은 그대로 유효하며, 오히려 인프로세스 Function 쪽 여유가 더 커졌습니다.

### A-6. 지식/RAG 관련 (v0.11.1)

- **[보안] 권한 밖 지식베이스 검색 노출 수정.** 접근 가능한 컬렉션 목록이 벡터 스토어에 전달된 뒤 조용히 무시되어, 권한 없는 지식베이스의 내용이 검색 결과에 섞일 수 있었습니다. **엠바고 자료나 데스크별 비공개 자료를 Knowledge에 넣을 계획이면 v0.11.1 미만은 사용 불가로 봐야 합니다.**
- **[회귀 수정] v0.11.0부터 깨져 있던 지식 검색과 그룹 공유 파일 읽기.** 임베딩 서비스에 사용자 정보를 전달하는 인스턴스에서 지식 검색이 실패하고, 지식이 비어 있는 것처럼 답변했습니다. 공유 파일 문제는 설정과 무관하게 모든 인스턴스에 해당했습니다.
- **`ENABLE_RAG_CSV_SUMMARY`**: CSV 파일의 행 수·데이터 행 수·열 수·열 이름을 모델에게 한 줄로 알려줍니다. **Data Analysis Desk에 직접 유용합니다.**
- **`ENABLE_KNOWLEDGE_FILE_RETENTION`**: 지식베이스에서 파일을 빼도 저장 파일과 검색 데이터를 삭제하지 않고 유지합니다.
- **`RAG_METADATA_MAX_VALUE_CHARS`**: 페이지 레이아웃·표·감지 언어 같은 대용량 추출 메타데이터를 벡터 스토어에 보관하지 않고, 남은 초과 값을 잘라냅니다. 읽는 도중 비정상적으로 팽창하는 문서가 메모리를 고갈시키는 것을 막습니다.
- **`TIKA_SERVER_VERSION`**: Apache Tika 4 지원 (기존에는 Tika 3만 인식).
- **[보안] 압축 폭탄 방어**: 저장 크기 대비 과도하게 팽창하는 Word/Excel/PowerPoint/OpenDocument/EPUB 파일을 읽기 전에 거부합니다.
- 지식베이스에 지정한 파일을 목록에서 바로 열어 읽을 수 있게 됨.
- 지식베이스 벡터 재생성 시 포함된 각 파일의 벡터도 함께 재생성 (이전에는 개별 파일 첨부 시 조용히 아무것도 못 찾음).
- **[회귀 수정]** v0.11.0부터 모델·폴더에 붙인 Knowledge를 채팅 밖에서 열 수 없던 문제 해소. Focused retrieval / 전체 문서 모드 전환이 다시 가능합니다.

### A-7. 채팅·워크플로우 신규 기능 (v0.11.1)

| 기능                       | 설명                                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **`ask_user` 내장 도구**   | 모델이 진행 전 최대 3개의 객관식 질문을 띄우고 대기. 직접 입력도 가능. 저장된 대화에서는 새로고침해도 질문이 유지됨   |

| **`/model` 명령**          | 메시지 박스에서 현재 모델 확인, id로 전환, 모델 선택기 열기                                                           |
| **첨부 업로드 중 전송**    | 업로드가 끝나지 않아도 메시지를 큐에 넣고 준비되면 자동 전송                                                          |
| **링크 첨부 개선**         | 붙여넣은 링크의 실체를 판별해 문서·이미지는 실제 첨부로 다운로드 (이전에는 전부 웹페이지 텍스트로 취급)               |
| **Sub-agent에 파일 전달**  | 위임 작업에 첨부 파일을 실어 보낼 수 있음. 이전에는 열 수 없는 파일 참조만 전달되고도 답변을 시도했음                 |
| **채팅 검색 개선**         | 정확한 구절이 아니라 입력한 모든 단어를 순서 무관하게 포함하는 대화를 검색. 정확 일치 우선 표시                       |
| **도구/스킬 검색창**       | 통합 메뉴에서 도구와 스킬을 이름으로 검색                                                                             |
| **API 키 삭제**            | 계정 설정에서 API 키를 교체가 아니라 폐기 가능                                                                        |
| **터미널 노출 범위 제어**  | 관리자가 관리형 터미널별로 채팅/Automation 노출 여부와 워크스페이스 공유 방식(전체 공유 / 채팅별 / Automation별) 지정 |

## 2. 신규 기능 상세 분석 (v0.11.0 기준, 2026-08 작성)

### 2-1. Sub-agents (v0.11.0)

모델이 작업의 일부를 백그라운드 헬퍼 에이전트에게 위임할 수 있는 기능입니다. 각 헬퍼는 자체적인 도구 기반 대화를 실행하고 결과를 메인 채팅으로 보고합니다.

**주요 특징:**

- 관리자가 Admin Settings에서 활성화해야 사용 가능 (기본 비활성)
- 동시 실행 수, 반복 횟수, 출력 상한, 공유 시스템 프롬프트 설정 가능
- 각 서브에이전트는 완전한 도구 접근 권한을 가진 별도 채팅으로 실행
- 추가 LLM 호출 비용 발생
- **[2026-09 갱신]** v0.11.1부터 위임 작업에 첨부 파일을 전달할 수 있습니다. v0.11.1에서 Sub-agent·타이머·Automation·채널이 시작한 대화도 토큰 사용량을 보고하도록 수정되었습니다 — **비용 추적이 가능해졌다는 뜻이므로, V2의 Sub-agent 팩트체크 실험 수용 기준에 "실험 기간 누적 토큰 비용" 항목을 넣을 수 있습니다.**

**MVP 영향:** MVP 단계에서는 여전히 비권장입니다(비용 예측 불가, 비결정적 실행, 디버깅 난이도). 다만 v0.11.1의 토큰 사용량 보고 덕분에 "실험 후 정량 판단"이 가능해졌습니다.

### 2-2. Calendar (신규 기능 섹션)

OpenWebUI에 내장된 개인 캘린더 기능입니다. 기존 가이드 파일에는 전혀 없는 완전 신규 기능 영역입니다.

**핵심 기능:**

- 월/주/일 뷰 지원, 색상 코딩, RRULE 반복 일정
- AI 에이전트 자율 관리: 모델이 자연어로 이벤트 생성/수정/삭제/검색 가능
- Automation 통합: 활성 Automation이 '예약 작업' 캘린더에 가상 이벤트로 표시
- 캘린더 공유: 사용자/그룹 단위 읽기/쓰기 권한 부여
- 참석자 RSVP 추적 (pending/accepted/declined/tentative)
- 리마인더 알림: Toast, 브라우저 알림, Webhook 지원
- `ENABLE_CALENDAR` 환경변수로 전역 제어 (기본 활성)

**[2026-09 갱신] v0.11.0의 Calendar는 버그가 많았고 v0.11.1에서 대거 수정되었습니다.** 날짜 이동 시 이벤트 소실, 반복 일정 시간대 오계산, 채팅으로 이벤트 수정 시 나머지 필드 소실, PostgreSQL에서 종료일 없는 캘린더 검색 실패, 리마인더 시간이 숫자가 아닌 이벤트 하나 때문에 전체 리마인더가 멈추는 문제 등입니다. **Calendar를 실제로 쓸 계획이면 v0.11.1 이상이 사실상 전제 조건입니다.**

**MVP 영향:** 편집회의 일정 관리, 보도자료 마감 추적 등에 활용 가능. 가이드 파일 신규 작성 필요.

### 2-3. MCP: Streamable HTTP 전용 + OAuth 2.1

v0.6.31부터 네이티브 MCP 지원이 추가되었으며, Streamable HTTP 트랜스포트만 지원합니다. SSE/stdio 방식의 MCP 서버는 mcpo 프록시를 통해 변환해야 합니다.

**변경 요약:**

- MCP 서버 등록은 관리자 전용 (Admin Settings → External Tools)
- 인증 모드: None, Bearer, OAuth 2.1 (DCR), OAuth 2.1 (Static)
- 사용자 정의 헤더에 `{{USER_ID}}`, `{{USER_EMAIL}}` 등 템플릿 토큰 지원
- OpenAPI와 MCP 도구를 혼용 가능
- OpenAPI가 여전히 권장 통합 경로 (엔터프라이즈 준비도, 운영 탄력성, 관측 가능성)
- **[2026-09 갱신]** v0.11.1에서 OAuth 사용 도구 서버 등록 UX 개선 (연결 대화상자에서 바로 계정 인증, 확인 버튼이 연결 실패 대신 로그인 정보를 검사). 세션 기반 도구 서버가 자기 연결에 속한 자격증명을 받도록 수정. `WEBUI_SECRET_KEY`가 바뀌어 저장된 로그인 정보를 복호화할 수 없을 때 서버 이름과 재연결 안내를 표시.

**MVP 영향:** FastAPI 서비스를 OpenAPI Tool Server로 등록하는 것이 기본 경로이며, MCP는 필요시 보조 수단으로 사용합니다.

### 2-4. Ecosystem 섹션 (신규)

OpenWebUI 코어 외부의 공식 프로젝트를 묶는 새로운 문서 섹션입니다.

**포함 프로젝트:**

- **Open Terminal & Terminals**: 기업용 오케스트레이터로 사용자별 워크스페이스 프로비저닝, 정책(이미지/도구/리소스/보안/정리) 관리
- **Open WebUI Computer**: 브라우저에서 전체 컴퓨터 환경 제공 (파일, 터미널, git, 에디터). 자체 에이전트 런타임 포함
- **Knowledge Base Sync (oikb)**: 폴더, 리포, 버킷, 위키 등의 소스를 Knowledge Base에 증분 동기화

**MVP 영향:** oikb를 활용하면 사내 스타일 가이드(AP Style, Korea Times House Style)의 Knowledge 동기화를 자동화할 수 있습니다. SG9 작업 시 검토 권장.

### 2-5. Fully Async 백엔드

OpenWebUI 백엔드가 완전 비동기(fully async)로 전환되었습니다. 동기/CPU 바운드 플러그인 코드는 워커 스레드 풀(`THREAD_POOL_SIZE`)로 오프로드됩니다.

**[2026-09 갱신] v0.11.1에서 `THREAD_POOL_SIZE`의 의미가 바뀌었습니다.** 이제 백그라운드 작업이 도는 **두 개의 풀 모두**를 제어합니다. 이전에는 하나만 제어했고, 지식 검색·로그인·파일 저장 같은 블로킹 작업 대부분을 담당하던 나머지 풀은 설정으로 올릴 수 없는 낮은 상한에 고정되어 있었습니다.

**실무 의미:** 이 값을 크게 잡아둔 인스턴스는 두 풀 합계로 **설정값의 최대 2배까지** 스레드를 쓰게 됩니다. 반대로 기존의 낮은 상한에 기대어 스레드 사용량을 억제하고 있었다면 재검토가 필요합니다.

- 장시간 실행 Tool/Function이 다른 사용자를 차단하지 않음
- GPU 접근, 대규모 의존성, 격리/독립 스케일링이 필요한 경우에만 외부 서비스 분리 필요

**MVP 영향:** 번역/요약 같은 경량 Tool은 인프로세스에서 실행해도 성능 문제가 없습니다. 교정/이미지 생성처럼 무거운 작업만 외부 FastAPI로 분리하는 하이브리드 전략이 합리적입니다. (이 판단은 v0.11.1의 스트리밍 재작성 이후 오히려 강화됨)

### 4-2. 신규 활용 기회

**1. Automation → 채널 게시로 편집회의 브리핑**

Automation의 대상을 채팅이 아니라 채널로 지정하면, 예약 실행 결과가 채널 메시지로 게시됩니다. 브리핑 결과를 개인 채팅에서 꺼내 공유하던 단계가 사라집니다.

**2. 도구 승인으로 Fact Checker 최소 구현**

팩트체크 도구를 승인 대상으로 두면, 기자가 "이 주장을 웹으로 검증하겠다"는 호출을 건별로 승인합니다. 코드 없이 사람이 개입하는 지점을 만들 수 있습니다.

**3. oikb로 스타일 가이드 자동 동기화**

AP Style Guide, Korea Times House Style 문서를 Git 리포나 공유 폴더에서 Knowledge Base로 자동 동기화. SG9에 직접 기여합니다.

**4. `DEFAULT_INTERFACE_SETTINGS`로 뉴스룸 기본값 고정**

기본 모델, 기본 토글 상태 등을 전사 기본값으로 지정하고, 손대지 않은 항목은 이후 기본값 변경을 계속 따라가게 합니다. 개별 구독 대체라는 프로젝트 목표에 가장 직접적인 수단입니다.

**5. `TASK_MODEL_PARAMS`로 요약 잘림 방지**

보도자료 요약·제목 생성의 토큰 상한이 이전에는 고정이었습니다. SG3 파이프라인 품질 검증 시 이 값을 먼저 조정하세요.

## 6. 업그레이드 주의사항 (v0.11.3 기준, 2026-09 전면 개정)

### 6-1. 권장 업그레이드 경로

**v0.10.x 또는 v0.11.0 → `v0.11.3` 태그로 직행.** 중간 버전을 거칠 이유가 없고, v0.11.3에만 마이그레이션 실패 처리 수정이 들어 있습니다.

태그는 반드시 `v0.11.3` 같은 고정 태그를 씁니다. `latest`, `main` 같은 부동 태그는 프로덕션에서 사용하지 않습니다 (프로젝트 기존 원칙).

### 6-2. 반드시 사전 조치할 항목

**1. DB 백업 (필수)**

v0.11.1에 스키마 변경이 포함됩니다. PostgreSQL 덤프를 먼저 뜨세요. 다운그레이드는 마이그레이션 이후 지원되지 않습니다.

**2. 롤링 업데이트 불가**

멀티 워커·멀티 서버·로드밸런싱 배포라면 **모든 인스턴스를 동시에 교체**해야 합니다. 스키마 비호환으로 애플리케이션이 실패합니다. 단일 서버 docker-compose 환경이면 `docker compose down` → `pull` → `up` 순서로 짧은 다운타임을 감수하는 편이 안전합니다.

**3. netcat / pytest / Docker SDK 제거 확인 (놓치기 쉬움)**

v0.11.1부터 컨테이너 이미지에서 pytest, pytest-docker, Docker SDK, netcat이 빠졌습니다. OpenWebUI 자체는 쓰지 않던 패키지라 제거된 것입니다.

**확인할 곳:**

- `docker-compose.yml`의 `healthcheck`가 `nc -z localhost 8080` 형태라면 **깨집니다.** `curl` 기반으로 교체하세요.
- 컨테이너 안에서 테스트를 돌리는 CI 스텝
- 이 패키지들에 의존하는 커스텀 Tool/Function

**4. `THREAD_POOL_SIZE` 재검토**

두 개 풀 모두를 제어하게 바뀌었습니다. 값을 크게 잡아뒀다면 실제 스레드 수가 최대 2배가 됩니다.

**5. `ENABLE_REALTIME_CHAT_SAVE` 무효화**

이 설정은 이제 아무 효과가 없습니다. 진행 중인 응답은 DB 밖에 보관되고 완료 시 한 번 기록됩니다. 환경변수에서 제거해도 됩니다.

**6. Redis 필요 기능 확인**

비밀번호 변경 시 기존 세션 무효화는 Redis가 있어야 동작합니다. Redis 없이 운영 중이면 무효화가 되지 않고 경고 로그만 남습니다.

**7. CSS 커스터마이징 재검증**

v0.11.0의 UI 전면 재설계 이후 v0.11.1~0.11.3에서도 사이드바, 설정 다이얼로그, 파일 브라우저, UI Scale 처리가 계속 바뀌었습니다. 브랜딩 패치는 **v0.11.3 기준으로 재작성**해야 합니다. 부분 수정이 아니라 전면 재검증으로 잡으세요.
